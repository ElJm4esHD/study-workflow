# Hito C: rediseño, dashboard y modelo de datos — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rediseñar la web (tema oscuro con tarjetas), agregar Inicio (dashboard), el calendario mes con chips por materia y el detalle del día, y sumar sigla a Materias, duración/categoría al To-do y el formato de importación v2.

**Architecture:** Mismo núcleo + módulos. Datos nuevos con migraciones SQL numeradas (más un backfill de siglas al arrancar). Lógica de presentación del calendario en un archivo puro con tests (`modules/calendar/web/summary.ts`). El dashboard se arma desde un campo nuevo opcional `dashboard` del contrato de módulo web.

**Tech Stack:** el de siempre (Node 24 + `node:sqlite` + Fastify 5; React 19 + react-router 8 + Vite 8 + TS 7; Vitest 5; FullCalendar 7 vía `@fullcalendar/react/*`). Sin dependencias nuevas.

**Spec:** `docs/superpowers/specs/2026-11-05-hito-c-rediseno-design.md`. Mockup aprobado: `docs/superpowers/specs/2026-11-05-hito-c-mockups.html` (la referencia visual: abrirlo y copiar proporciones, tamaños y textos). Leer también `CLAUDE.md`.

## Global Constraints

- **Ejecución secuencial**, una tarea por vez. Rama `main` (pedido del usuario).
- Antes de usar una API de FullCalendar, Fastify, react-router o `node:sqlite` que no esté ya usada en el repo, **consultar Context7**. No escribir firmas de memoria.
- **Sin dependencias nuevas.**
- TS: `erasableSyntaxOnly`, imports relativos con extensión `.ts`/`.tsx`, `"type": "module"`.
- DB en `snake_case`, API en `camelCase`; mapeo en los services. Migraciones SQL numeradas por módulo (`002_*.sql`).
- Errores de API: `{ "error": { "code", "message" } }`, mensaje en español rioplatense.
- UI en español (Argentina, voseo), fechas visibles `dd/mm/aaaa` (o `dd/mm` donde el mockup lo usa), semana desde el lunes, zona `America/Argentina/Buenos_Aires`.
- Un módulo no toca tablas de otro: usa `ctx.services`/la API. Toda llamada HTTP del front pasa por `core/web/api.ts`.
- **Tema:** oscuro siempre, `color-scheme: dark`; todos los colores son variables CSS en `:root` de `core/web/styles.css` (los CSS de módulos solo usan variables). Tokens: `--bg #10131a`, `--surface #191e28`, `--surface-2 #222937`, `--line #2b3342`, `--text #e6e9f0`, `--muted #98a1b3`, `--faint #7b859b`, `--accent #b7c4ff`, `--on-accent #141a33`, `--late #ffadad`, `--entrega #ffd38a`.
- Esquinas: tarjetas 12 px, controles 10 px, chips 4–6 px. Tipografía `system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue', sans-serif`; números `tabular-nums`. Sin fuentes externas.
- Animaciones: 160 ms `cubic-bezier(.2,.7,.3,1)`, solo como respuesta a una acción; `prefers-reduced-motion` las apaga. Sin rebotes.
- Accesibilidad: zonas táctiles ≥ 44 px (48 en filas y botones principales), labels, foco visible, contraste AA.
- Commits chicos, en español con prefijo (`feat:`, `fix:`, `test:`, `docs:`), terminados en línea en blanco + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Autor = config global de git.
- Tests: `npm test` y `npm run typecheck`; el front además `npm run build`.

## Review Focus

1. **Nombre de materia que no da sigla** ("De la", "C++", "  ") → la generación cae a las primeras 3 letras/dígitos del nombre sin filtrar y, si no hay ninguno, `MAT`; nunca devuelve `''`. Test en Task 1.
2. **Base existente con colores fuera de la paleta o ya pastel** → la migración no rompe; el backfill de siglas al arrancar es idempotente (correr `buildApp` dos veces sobre la misma base no cambia siglas editadas). Test en Task 2.
3. **Clientes que no mandan los campos nuevos** (agregar rápido, el commit de importación v1, PATCH parcial) → `category` queda `'tarea'`, `durationMin` queda como estaba; `durationMin: null` borra la estimación. Test en Task 3.
4. **`duracion` con tipo raro** (`"45"`, `45.5`, `0`, `1441`) → error por ítem; `categoria` en un ítem `parcial` se ignora sin error. Test en Task 4.
5. **Días cargados**: más materias que chips, dos exámenes el mismo día, examen sin materia (va en el fuerte neutro) y evento de varios días (cuenta en cada día que cubre). Test en Task 7.
