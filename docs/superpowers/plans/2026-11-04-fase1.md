# Study Workflow Fase 1: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir el backend y la web de Study Workflow (núcleo modular, Materias, To-do, Importar plan y Calendario) y dejarla deployada en `tu-server` detrás de `tailscale serve`.

**Architecture:** Un núcleo chico (DB, migraciones, registro de módulos, Materias, settings, shell web) más módulos en `modules/<id>/{server,web}` que se registran en `modules/server.ts` y `modules/web.ts`. Fastify sirve `/api/*` y el build de Vite desde un solo contenedor. SQLite con `node:sqlite`; Node ejecuta los `.ts` directamente, sin paso de build en el server.

**Tech Stack:** Node 24 (local 24.18), `node:sqlite`, Fastify 5.12, @fastify/static 10, React 19.3, react-router 8, Vite 8, TypeScript 7, Vitest 5, FullCalendar 7.1 (MIT: core, react, daygrid, timegrid, list, interaction), @dnd-kit/core 6 + sortable 10, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-11-04-fase1-design.md`. Leer también `CLAUDE.md`.

## Global Constraints

- **Ejecución secuencial**, una tarea por vez. Nada de agentes en paralelo.
- Antes de usar una API de Fastify, Vite, react-router, FullCalendar, dnd-kit, `node:sqlite` o Tailscale, **consultar la doc actual con Context7**. Si Context7 no está disponible, usar la doc oficial con WebFetch. No escribir firmas de memoria.
- Dependencias permitidas: solo las de la tabla de la sección 3 del spec. Cualquier otra se pregunta antes.
- TS: `erasableSyntaxOnly` (sin `enum`, sin parameter properties, sin `namespace`), imports relativos con extensión `.ts`/`.tsx`, `"type": "module"`.
- DB en `snake_case`, API JSON en `camelCase`. El mapeo se hace en los services.
- Fechas de usuario: `YYYY-MM-DD` / `HH:MM`, hora local AR, como texto. Timestamps: ISO UTC (`new Date().toISOString()`).
- Errores de API: `{ "error": { "code": string, "message": string } }`, con mensaje en español rioplatense.
- UI en español (Argentina, voseo), fechas visibles `dd/mm/aaaa`, semana desde el lunes, zona `America/Argentina/Buenos_Aires`.
- Cada módulo solo toca tablas con su prefijo. Para otro módulo usa `ctx.services.get<T>(id)`; para materias, `ctx.materias`.
- Toda llamada HTTP del frontend pasa por `core/web/api.ts`.
- Accesibilidad: zonas táctiles ≥ 48px, labels, contraste AA.
- Commits chicos, mensajes en español con prefijo (`feat:`, `test:`, `chore:`, `docs:`) y terminados en `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Autor = config global de git (no pasar `-c user.*`).
- Comandos de test: `npm test` (= `vitest run`) y `npm run typecheck` (= `tsc --noEmit`).

## Review Focus

1. **Llaves sueltas antes del plan.** Si el texto pegado tiene `{` en la prosa o un JSON que no es el plan antes del bloque real, el parser tiene que seguir buscando y encontrar el plan. Test en Task 6.
2. **Reimportar el mismo plan.** La segunda vista previa debe marcar todos los ítems como duplicados y dejarlos destildados. Test en Task 7.
3. **Crear una materia que ya existe.** Si en el commit llega `create` con un nombre cuyo `name_key` ya existe (porque se creó entre la vista previa y el guardado, o solo cambia una tilde), se reusa la existente en vez de devolver un error. Test en Task 7.
4. **Borrar un plan cuyos ítems ya borraste a mano.** No hay error y el progreso excluye los faltantes. Test en Task 7.
5. **Materias archivadas.** `GET /api/materias` las sigue devolviendo con `archived: true` para que los ítems viejos mantengan su color, y los selectores las ocultan. Test en Task 3.
