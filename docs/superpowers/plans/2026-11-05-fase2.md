# Fase 2: APK con Capacitor — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** APK Android firmado, con el frontend adentro, que abre sin conexión con la última copia, deja tildar tareas offline (las sincroniza al volver) y recibe texto desde "Compartir" para Importar.

**Architecture:**
- La caché y la cola viven en el núcleo web (`core/web/offline.ts` puro + `core/web/api.ts`). Los módulos solo leen el estado de conexión y declaran qué precargar.
- Capacitor 8 envuelve el mismo build de Vite. El proyecto nativo `android/` va commiteado (la Fase 3 suma ahí los widgets). Compartir se hace con un plugin local en Kotlin dentro del proyecto, sin plugins de terceros.
- El backend agrega CORS para `https://localhost`.

**Tech Stack:** el de siempre (Node 24, Fastify 5, React 19, react-router 8, Vite 8, TS 7, Vitest 5), más Capacitor 8 (`@capacitor/core`, `@capacitor/cli`, `@capacitor/android`, y `@capacitor/app` solo si hace falta para el botón Atrás). Android Studio instalado en esta compu: JBR en `C:\Program Files\Android\Android Studio\jbr` (JDK 25) y SDK en `%LOCALAPPDATA%\Android\Sdk` (platform android-37, build-tools 36.0.0, licencias aceptadas).

**Spec:** `docs/superpowers/specs/2026-11-05-fase2-apk-design.md` (aprobado por el usuario). Leer también `CLAUDE.md`.

## Global Constraints

- **Ejecución secuencial**, en la rama `main`.
- **Context7 antes de cualquier API de Capacitor, Android/Gradle o Fastify** que no esté ya usada en el repo. Las IDs son `/ionic-team/capacitor/8.6.0` y `/websites/capacitorjs`. No escribir firmas de memoria.
- **Dependencias:** solo las de Capacitor del Tech Stack. Cualquier otra se pregunta antes.
- **TS:** `erasableSyntaxOnly`, imports relativos con extensión, `"type": "module"`.
- **Errores de API:** el formato es `{ "error": { "code", "message" } }`, en español rioplatense.
- **Textos exactos:**
  - Aviso: `Sin conexión. Datos del dd/mm hh:mm.`, más `, N cambios por sincronizar` cuando N > 0 (`1 cambio` en singular).
  - Acción bloqueada: `Sin conexión: solo podés tildar tareas.`
  - Sin copia: `Sin conexión y sin datos guardados para esta pantalla.`
  - Falla al conectar: `No pude conectar con el servidor. ¿Tailscale está prendido en el celu?`
- **URL del servidor por defecto:** `https://tu-server.tu-tailnet.ts.net:8443`. **Origen de la app:** `https://localhost`.
- **Timeouts:** 8 s para GET y 30 s para los demás métodos.
- **Único encolable:** `PATCH /api/todo/:id` con cuerpo exactamente `{ completed: boolean }`.
- **Tema y accesibilidad:** el tema oscuro del Hito C (solo variables CSS) y zonas táctiles ≥ 44 px.
- **Android:**
  - `appId` `ar.federico.studyworkflow`, `appName` `Study Workflow`.
  - Keystore en `%USERPROFILE%\.study-workflow\release.jks`, con la clave en `%USERPROFILE%\.study-workflow\keystore.properties`. **Nunca dentro del repo.**
  - `versionCode` = minutos desde 2026-01-01T00:00Z.
- **Commits:** chicos, en español con prefijo, terminados en línea en blanco + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Tests:** `npm test`, `npm run typecheck` y `npm run build`. Las tareas nativas además corren `npm run apk`.

## Review Focus

1. **Tildar y destildar la misma tarea offline** → la cola queda con un solo op con el estado final, y al sincronizar el servidor termina en ese estado. Test en Task 2.
2. **La tarea se editó desde la compu mientras el celu estaba offline** → el tilde se descarta y no pisa el cambio. Test en Task 2.
3. **El servidor se cae en medio de la sincronización** → los ops que no se mandaron siguen en la cola, sin duplicados ni pérdidas. Test en Task 2.
4. **Primera apertura sin conexión o pantalla nunca abierta online** → error claro con el texto exacto, nunca una pantalla en blanco. Test en Task 2 (api) y verificación en Task 3.
5. **Texto compartido largo (≥ 20 000 caracteres) o compartido antes de configurar el servidor** → llega entero a Importar después de "Conectar". Verificación en Task 7.

### Task 2: Caché offline y cola de tildes (núcleo)

**Files:**
- Create: `core/web/offline.ts`, `core/web/offline.test.ts`, `core/web/server.ts`
- Modify: `core/web/api.ts`, `core/web/api.test.ts`

**Interfaces:**
- Produces, en `core/web/server.ts`:
  - `DEFAULT_SERVER = 'https://tu-server.tu-tailnet.ts.net:8443'`
  - `isNative(): boolean`, que usa `Capacitor.isNativePlatform()`. Hasta la Task 5, `@capacitor/core` no está instalado: dejarlo como `false` con el comentario `// Task 5`, o instalar solo `@capacitor/core` acá.
  - `getServerUrl(): string | null`, `setServerUrl(url: string): void`, en `localStorage` con la clave `sw.server`.
  - `apiBase(): string`, que devuelve `''` en la web y la URL guardada en nativo.
- Produces, en `core/web/offline.ts`. Todo es puro; recibe un `Store = { get(k: string): string | null; set(k: string, v: string): void }` y por defecto usa `localStorage`. Las claves llevan el prefijo `sw.`.
  - `saveCopy(url: string, data: unknown, at: string): void` y `readCopy<T>(url: string): { data: T; at: string } | undefined`.
  - `lastCopyAt(): string | null`: el `at` más reciente.
  - `isQueueable(method: string, path: string, body: unknown): boolean`.
  - `type QueueOp = { id: string; completed: boolean; baseUpdatedAt: string | null; at: string }`.
  - `enqueue(id: string, completed: boolean, at: string): QueueOp`. Toma `baseUpdatedAt` de la primera copia donde aparece ese `id` y colapsa por `id` (se queda con el `completed` final y el `baseUpdatedAt` original).
  - `pending(): QueueOp[]`.
  - `patchCopies(id: string, completed: boolean, at: string): void`. Recorre todas las copias y en todo objeto con `id === id` y la clave `completed` setea `completed` y `completedAt` (`at` si es `true`, `null` si es `false`).
  - `flush(req: (method: 'GET' | 'PATCH', path: string, body?: unknown) => Promise<{ status: number; json: unknown }>): Promise<{ sent: number; dropped: number; remaining: number }>`. Procesa en orden:
    - Hace `GET /api/todo/:id`. Si da 404, descarta el op. Si el `updatedAt` es distinto de `baseUpdatedAt`, también lo descarta.
    - Si no, hace `PATCH { completed }` y saca el op.
    - Si `req` tira error de red, corta y deja ese op y los que siguen.
- Produces, en `core/web/api.ts`:
  - `api()` sigue con la misma firma, pero usa la URL `apiBase() + path`, con `AbortSignal.timeout(8000)` en los GET y `30000` en los demás métodos.
  - **GET exitoso:** guarda la copia y marca online.
  - **GET con falla de red:** devuelve la copia y marca offline. Si no hay copia, tira `ApiError(0, 'sin_conexion', 'Sin conexión y sin datos guardados para esta pantalla.')`.
  - **No-GET encolable**, con falla de red o ya offline: `enqueue` + `patchCopies` y devuelve el objeto parcheado de la copia de `/api/todo/:id`, o `undefined`.
  - **No-GET no encolable:** offline o con falla de red, tira `ApiError(0, 'sin_conexion', 'Sin conexión: solo podés tildar tareas.')`.
  - `type Connection = { offline: boolean; pending: number; copyAt: string | null }`, `getConnection(): Connection`, `onConnection(fn: (c: Connection) => void): () => void`.
  - `resync(): Promise<void>`: `GET /api/health` y, si anda, `flush`, marca online y emite el evento de recarga.
  - `useApi` se suscribe a ese evento y recarga (`reload`).
